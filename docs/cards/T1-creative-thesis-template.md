# T1 (creative, Claude): the thesis template (Overleaf project `thesis/`)

Read `docs/cards/common_rules.md` (below). You build the LaTeX template only. A later card (W3)
writes the paper into it. Look at `writeup/main.tex` and `writeup/main.pdf` for the current paper's
structure, figures, tables, number macros and TikZ diagrams the template must carry.

**Owner's brief (Augusto, 2026-11-01):** a single LaTeX paper, about 20 pages of main text plus
about 10 pages of references and appendix, ready for an arXiv preprint, built on an Overleaf
"thesis template" customized to his aesthetic.

**His aesthetic (from his standing preferences):** "Cool Kaffeehaus": oxblood, sand and cream
accents, Times-like serif body with a Helvetica-like sans for headings and labels, numbered
sections, zebra-striped tables (booktabs, light sand stripes), restrained use of colour, generous
margins, careful typography (microtype). Never vanilla. Aesthetics matter as much as content to
him, and he decides by looking. The current writeup uses a monospaced grey look; keep that as a
second option.

**Acceptance:**
1. `thesis/` is a self-contained Overleaf project that compiles with `latexmk` on stock TeX Live
   (pdfLaTeX preferred; arXiv accepts pdfLaTeX). Files: `ecnthesis.cls` (or `.sty` + `main.tex`),
   `main.tex`, `refs.bib` (biblatex/biber or natbib/bibtex: pick what arXiv accepts and say which),
   `latexmkrc`, `figures/` (empty or `.gitkeep`; E3 fills it), `README.md` (how to compile, how to
   upload to Overleaf, how to switch the look).
2. One class option switches the look: `kaffeehaus` (default) or `mono` (close to the current
   writeup). Everything else (structure, macros) is identical between the two.
3. The template provides: a title page (title, subtitle, author Augusto González-Bonorino, Arizona
   State University, ECN 593 applied project, date, abstract, keywords, JEL codes), a short
   status/disclosure box style, theorem-like environments (definition, assumption, remark), a
   zebra table style, a figure caption style, an appendix style, a references style, running
   headers, and `\input{numbers}` (the file is generated by E3 later; guard it with
   `\InputIfFileExists{numbers}{}{}` so the template builds before it exists).
4. A sample `main.tex` that exercises every element with placeholder text (no result numbers), one
   table, one figure placeholder, one TikZ diagram, one appendix and five references.
5. Build it, then render pages 1–4 and one appendix page of both looks to PNG
   (`pdftoppm -r 80`) into `thesis/shots/` and look at them yourself. Zero `Overfull`, zero `^!`,
   zero undefined references. Fix what looks wrong before handing off.
6. Commit only `thesis/` paths (not `thesis/numbers.tex`, not `thesis/figures/*.png`: those belong
   to E3). LaTeX build products under `thesis/` are already gitignored (PM, 2026-11-01); do not
   edit `.gitignore`. If you need another pattern, say so in the handoff.

**Artifact:** the commit sha, the shot paths, and one paragraph on the design choices.
Progress file: `docs/cards/progress/T1.md`.

**Fence:** write only `thesis/`. Do not touch `writeup/`, code,
results or the spine.
